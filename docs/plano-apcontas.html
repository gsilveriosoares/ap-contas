ApContas · plano de implementação

Um portal de finanças pessoais que começa pelas contas do mês

Primeiro: saber o que vence, quanto falta pagar e quanto sobra. Depois: saldo das contas, reservas para guardar dinheiro e lembretes. Todos os cálculos são feitos no próprio sistema, sem IA e sem gastar tokens.

Front-endAngular 22 + Bootstrap 5.3

O projeto já criado, com Bootstrap via npm e componentes do ng-bootstrap.

Back-endSupabase

Banco Postgres, login e regras de acesso prontos. Não tem servidor para manter.

PublicaçãoCloudflare Pages + PWA

Grátis, publica a cada push no GitHub e instala no celular como um app.

Front-end

Boas práticas com Bootstrap no Angular

  • Instalar pelo npm, não por CDN: bootstrap e bootstrap-icons. No styles.scss, mudar as variáveis (cor $primary, bordas, fonte) antes de importar o Bootstrap, para o tema ficar seu e não com cara de "Bootstrap padrão".
  • Importar só o que usa: os parciais SCSS (grid, cards, forms, buttons, utilities, nav…), o que deixa o CSS menor.
  • Componentes interativos com ng-bootstrap (modal, offcanvas, datepicker, toast). Ele é feito para Angular e dispensa o JS do Bootstrap e o jQuery.
  • Mobile-first: escrever primeiro para o celular e abrir colunas nos breakpoints (col-12 col-md-6 col-xl-3). Botões e itens de lista com pelo menos 44px de altura para o toque.
  • Utilitários antes de CSS próprio: usar d-flex, gap-2 e text-body-secondary. CSS próprio só dentro de componentes reutilizáveis (CardResumo, ItemConta, BadgeVencimento).
  • Tema escuro de graça: o Bootstrap 5.3 tem data-bs-theme="dark". Basta seguir a preferência do celular.
  • Dinheiro e datas em pt-BR: registrar o locale pt-BR e usar currency:'BRL' e date:'dd/MM'. Guardar valores em centavos (inteiro), nunca em número com vírgula flutuante, para as somas não errarem.
  • Formulários reativos com as classes de validação do Bootstrap (is-invalid e invalid-feedback) e mensagens claras ("Informe o vencimento").
  • Acessibilidade: todo campo com <label>, contraste bom e situação mostrada com texto e cor juntos ("Atrasada" em vermelho, não só vermelho).

Organização das pastas no Angular (componentes standalone, signals e rotas carregadas sob demanda):

src/app/
├─ core/            → login, cliente Supabase, guards, layout (menu lateral + barra inferior)
├─ shared/          → componentes reutilizáveis, pipes (moeda, “vence em X dias”)
├─ features/
│  ├─ inicio/       → resumo do mês
│  ├─ contas/       → lista, nova/editar conta, recorrências
│  ├─ dinheiro/     → contas bancárias e receitas      (fase 2)
│  └─ reservas/     → cofrinhos e metas                (fase 3)
└─ app.routes.ts
Back-end

Opções de back-end

O back-end precisa guardar os dados com segurança, separar os dados de cada usuário e fazer as contas (totais, recorrências, saldo previsto). As três opções abaixo resolvem isso sem IA.

OpçãoO que éPrósContras
SupabasePostgres na nuvem com login, API e regras de acesso prontasBanco relacional (ótimo para somas e relatórios); login por e-mail ou Google; RLS garante que cada pessoa só vê os próprios dados; zero servidor para cuidarNo plano grátis o projeto pausa após ~1 semana sem uso (reativa no painel); limite de 500 MB, que sobra para finanças pessoaisRecomendado
FirebaseBanco NoSQL (Firestore) do Google, com loginMuito simples; funciona offlineSomas e relatórios ficam no app, porque o banco não faz SUM/GROUP BY de forma prática; dados financeiros se encaixam melhor em tabelasAlternativa
API própriaNestJS (Node) ou .NET + Postgres (Neon), hospedada no RenderControle total; bom aprendizado; regras complexas no servidorBem mais código; no plano grátis o servidor "dorme" e a primeira abertura demoraPara depois

Como deixar o back-end "bom" desde o início

  • Cálculos no banco: uma view resumo_mes devolve o total, o pago, o pendente, as atrasadas e a sobra. O app só exibe.
  • Recorrências: uma tabela guarda a regra ("aluguel, todo dia 20") e uma função SQL gera as contas do mês. Parcelas funcionam do mesmo jeito.
  • Segurança: RLS em todas as tabelas (usuario_id = auth.uid()). A chave pública do Supabase pode ficar no front sem risco.
  • Separação: no Angular, um serviço por assunto (ContasService…) fala com o Supabase. Se um dia migrar para API própria, só esses serviços mudam.
  • Migrações versionadas: o SQL das tabelas fica no repositório (supabase/migrations), e tudo pode ser recriado do zero.

Publicação

Onde publicar de graça para usar no celular

Todas as opções abaixo dão HTTPS e endereço próprio, e publicam sozinhas a cada push no GitHub. Com o Angular virando PWA (ng add @angular/pwa), o site ganha ícone na tela inicial e abre em tela cheia, como um app. No Android: Chrome → menu → "Instalar app". No iPhone: Safari → Compartilhar → "Adicionar à Tela de Início".

ServiçoPor que considerarAtenção
Cloudflare PagesBanda generosa no plano grátis, rede rápida no Brasil, configuração simples para AngularConfigurar o redirecionamento de rotas da SPA (arquivo _redirects)Recomendado
VercelA mais fácil de configurar; preview para cada branchPlano grátis (Hobby) só para uso pessoal, não comercialAlternativa
NetlifyParecida com a Vercel, painel simplesPlano grátis com limite mensal de usoAlternativa
GitHub PagesFica no mesmo lugar do código (o repositório já é público)Precisa de truque para as rotas (404.html); o deploy é feito via GitHub ActionsAlternativa
Firebase HostingBoa opção se escolher Firebase como back-endExige conta Google Cloud configuradaSe usar Firebase

Os limites dos planos grátis mudam de tempos em tempos; vale conferir no site de cada serviço na hora de criar a conta.

Plano de implementação

Fases, do simples ao completo

Cada fase termina com algo usável no celular. A fase seguinte só começa quando a anterior estiver em uso e a necessidade aparecer.

0Agora

Fundação

  • Terminar o GitHub: login no gh, primeiro commit e repositório público ap-contas
  • Instalar Bootstrap, Bootstrap Icons e ng-bootstrap; tema com a cor principal do ApContas
  • Layout base: barra inferior no celular e menu lateral no computador, com rotas vazias
  • Locale pt-BR (moeda e datas)
  • PWA e publicação automática no Cloudflare Pages
Pronto quando: você abre o endereço no celular, instala na tela inicial e navega entre as telas.
1Próxima

Contas a pagar

  • Projeto no Supabase, tabelas da fase 1 e RLS
  • Login por e-mail
  • Cadastrar, editar e excluir contas; marcar como paga
  • Contas mensais e parceladas geradas automaticamente
  • Tela Início com total do mês, pago, a pagar e atrasadas; tela Contas com filtros
Pronto quando: todas as suas contas reais do mês estão lá e você sabe quanto falta pagar.
2Depois

Quanto dinheiro eu tenho

  • Contas financeiras (banco, carteira) com saldo inicial
  • Receitas (salário, extras); pagar uma conta baixa o saldo
  • Saldo atual e "sobra prevista" = saldo + receitas a receber − contas a pagar
Pronto quando: o app mostra quanto vai sobrar no fim do mês.
3Depois

Guardar dinheiro

  • Reservas com meta e data-alvo; guardar e retirar
  • Sugestão calculada: quanto guardar por mês para chegar à meta, ou guardar X% da sobra
Pronto quando: você acompanha o progresso das metas no celular.
4Conforme precisar

Evoluções

  • Lembrete de vencimento por e-mail ou notificação (tarefa agendada no Supabase)
  • Relatórios por categoria e comparação entre meses
